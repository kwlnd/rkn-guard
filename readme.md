# 🛡️ rkn-guard

Утилита для Linux-серверов: держит в `ipset` списки подсетей сканеров РКН,
ТСПУ/СКИПА и госорганов и отбрасывает их входящий трафик в `iptables` до того,
как он дойдёт до ваших сервисов. Снижает шанс, что ваш IPv4 попадёт в базы
сканирований и станет недоступен из РФ.

Форк [Flecksis/rkn-guard](https://github.com/Flecksis/rkn-guard): вместо баш-меню на
800 строк — один бинарник с нормальными подкомандами, плюс исправления ниже.

## Установка

Нужны Linux с systemd и root. Зависимости (`ipset`, `iptables`, `python3`,
`rsyslog`, `logrotate`) установщик ставит сам на Debian/Ubuntu и RHEL-подобных.

```bash
curl -fsSL https://raw.githubusercontent.com/kwlnd/rkn-guard/master/install.sh | sudo bash
```

Скрипт скачивает бинарник последнего релиза, сверяет sha256 с `checksums.txt`
и запускает `rkn-guard install`. Аргументы передаются дальше:
`... | sudo bash -s -- install --no-schedule`. Конкретная версия: `RKN_GUARD_VERSION=v3.0.0`.

Если бинарник уже скачан: `sudo ./rkn-guard install` — он сам скопируется в
`/usr/local/bin`. Короткое имя `rkn` — ссылка на `rkn-guard`.

### Что делает install

* скачивает списки, схлопывает пересекающиеся подсети, добавляет ручные баны;
* создаёт цепочку `SCANNERS-BLOCK` (ESTABLISHED → LOG с лимитом → DROP) для IPv4 и IPv6;
* **UFW активен** — встраивает правила в `before.rules`/`before6.rules` и делает `ufw reload`;
* **UFW нет или выключен** — подключает цепочку к `INPUT`. UFW rkn-guard никогда не включает;
* ставит `antiscan-ipset-restore.service`: при загрузке он до UFW поднимает наборы
  из `/etc/ipset.conf` и, без UFW, саму цепочку (`rkn-guard restore`);
* настраивает журнал и статистику (`--no-logging` — без них);
* включает автообновление списков ежедневно в 06:00 по времени сервера, если
  расписания ещё нет (`--no-schedule` — не включать).

Повторный `install` безопасен: счётчики, статистика и расписание сохраняются.

## Команды

```text
sudo rkn-guard status                  что работает: наборы, цепочка, отброшено пакетов, расписание
sudo rkn-guard update                  скачать списки и подменить наборы (счётчики не сбрасываются)

sudo rkn-guard ban 203.0.113.7 2001:db8::/48     ручной бан, IPv4 и IPv6
sudo rkn-guard unban 203.0.113.7
sudo rkn-guard bans

sudo rkn-guard sources                 списки: b1… встроенные, 1… ваши
sudo rkn-guard sources add <url>       добавить и сразу применить (--disabled — выключенным)
sudo rkn-guard sources disable b3      выключить встроенный
sudo rkn-guard sources remove 2

sudo rkn-guard schedule                текущее расписание
sudo rkn-guard schedule daily 06:00,18:30        по Москве (--local — по времени сервера)
sudo rkn-guard schedule every 6                  каждые 6 часов
sudo rkn-guard schedule off

sudo rkn-guard stats                   топ адресов из журнала с ASN и именем сети
sudo rkn-guard logs -f                 журнал IPv4 в реальном времени (-6 — IPv6)
sudo rkn-guard upgrade                 обновить сам rkn-guard (--check — только проверить)
sudo rkn-guard uninstall               снять защиту и удалить (--purge — вместе с данными)
```

`rkn-guard <команда> --help` — подробности, `-v` — показать системные команды.

Коды выхода: `0` — успешно, `1` — ошибка (действующие наборы не тронуты),
`2` — часть источников недоступна, для них взяты последние проверенные копии.

## Списки

LISTS_SECTION

Встроенные списки целиком заменяются файлом `/etc/rkn-guard-sources.list`
(один URL на строку, `#` — комментарий). Свои списки — `rkn-guard sources add`:
HTTP(S), один IPv4/IPv6 CIDR на строку, ссылки `github.com/.../blob/...` переводятся
на raw. Список проверяется целиком до сохранения: битая строка, `/0`, ответ больше
4 МиБ отклоняют его. До 32 своих списков, до 65536 подсетей на семейство.

Каждый источник обновляется отдельно; если он недоступен или вернул мусор,
используется его последняя проверенная копия. Настройки и копии лежат в
`/var/lib/rkn-guard/sources.json`, ручные баны — в `/var/lib/rkn-guard/bans.list`.

## Статистика

`status` показывает точное число отброшенных пакетов (счётчики правил DROP).
`stats` — выборка из журнала: правило LOG ограничено 10 записями в минуту,
так что это топ источников, а не полный счёт.

Журналы: `/var/log/iptables-scanners-{ipv4,ipv6}.log` (ротация logrotate, 7 дней).
Агрегат: `/var/lib/rkn-guard/attack-stats.json` и CSV
`/var/log/iptables-scanners-aggregate.csv` (разделитель `|`), обновляются каждые 30 секунд
таймером `antiscan-aggregate.timer`.

## Что исправлено относительно оригинала

* **Установщик ставил пакет `ufw`, а `full` делал `ufw --force enable`.** На сервере
  с выключенным UFW это закрывало все порты, кроме SSH (VPN, веб и т.д.), а на
  свежем Debian/Ubuntu установка падала на проверке SSH. Теперь UFW не ставится и не включается.
* **Ручные баны пропадали после первого обновления** — они писались прямо в рабочий
  набор, а `update` его подменял. Теперь баны хранятся отдельно и входят в каждую сборку.
* Бан IPv6 был невозможен: всё шло в IPv4-набор.
* Разбан подставлял IP в регулярное выражение `sed` и всегда писал «успешно».
* «Атак отбито» в меню считалось по правилу LOG с лимитом 10/мин — сильно заниженно.
* Наборы заполнялись отдельным процессом `ipset add` на каждую подсеть; теперь
  одним `ipset restore`.
* Пересекающиеся и вложенные подсети разных источников не схлопывались: из ~4400
  записей ~40% были лишними.
* Бинарник и меню скачивались без проверки контрольных сумм; self-update делал `curl | bash`.
* `full` без `--urls` падал с паникой и стектрейсом; бинарник без меню был непригоден —
  встроенные списки жили только в баш-скрипте.

### Переход со старой версии

Старые установки подхватываются: `rkn-guard install` (или `upgrade`) переносит ручные
баны из `/opt/rkn-guard-manual.list`, расписание из `/etc/rkn-guard-update.conf`,
отключённые встроенные списки и копии из `sources.json`, переводит таймер на новый
бинарник и удаляет `/opt/rkn-guard-manager.sh`. Старые имена `full`, `setup-logging`
и `build-info` работают, но скрыты из справки.

## ⚖️ Правовой статус и легальность

### Что это такое юридически?

**rkn-guard** является легальным инструментом сетевой безопасности класса «firewall» (межсетевой экран).

### Правовая квалификация

1. **Это обычный firewall** — rkn-guard использует стандартные механизмы Linux (`iptables`/`ipset`), которые являются штатными компонентами операционной системы для управления сетевым трафиком.
2. **Законное право на защиту** — владелец сервера/инфраструктуры имеет полное законное право контролировать входящие соединения и блокировать нежелательный трафик.
3. **Аналог антивируса** — так же как антивирус блокирует вредоносные программы, rkn-guard блокирует подозрительный сетевой трафик.

### Что делает утилита с точки зрения закона?

* ✅ Блокирует входящие подключения к **вашему** серверу с определённых IP-адресов
* ✅ Не осуществляет атаки на другие системы
* ✅ Не перехватывает чужой трафик
* ✅ Не нарушает работу других систем
* ✅ Защищает только вашу инфраструктуру

Это аналогично тому, как вы закрываете дверь в свой дом или устанавливаете сигнализацию.

### Правовые основания (Российская Федерация)

**Статья 16 Федерального закона от 27.07.2006 N 149-ФЗ «Об информации»:**  
> Владелец информационной системы вправе устанавливать ограничения доступа к информации

**Статья 209 ГК РФ (право собственности):**  
> Собственник вправе по своему усмотрению совершать в отношении принадлежащего ему имущества любые действия

**Федеральный закон от 27.07.2006 N 152-ФЗ «О персональных данных»:**  
> Оператор обязан принимать необходимые меры по защите персональных данных

### Может ли быть привлечение к ответственности?

**НЕТ**, если вы:

* Используете утилиту для защиты **собственной** инфраструктуры
* Блокируете только **входящий** трафик на свой сервер
* Не используете для атак или нарушения работы других систем

**rkn-guard НЕ является:**

* ❌ Средством взлома
* ❌ Инструментом DDoS-атак
* ❌ ПО для незаконного доступа к информации
* ❌ Средством обхода защиты

Вы имеете право решать, кто может подключаться к вашему серверу.

### Для государственных органов

Если представители правоохранительных органов интересуются этой утилитой:

**rkn-guard** — это стандартный межсетевой экран (firewall), который:

1. Использует только легальные системные компоненты Linux (`iptables`, `ipset`)
2. Блокирует входящие соединения к защищаемому серверу
3. Не осуществляет никаких активных действий в сторону других систем
4. Является инструментом защиты информации, аналогичным коммерческим решениям (Cisco ASA, pfSense и т.д.)
5. Реализует требования по защите информации согласно 152-ФЗ и другим нормативным актам

Использование данной утилиты является законным осуществлением права на защиту собственной информационной инфраструктуры.

### Рекомендации

* ✅ Используйте для защиты собственных серверов ^)
* ✅ Документируйте настройки безопасности
* ✅ Храните логи в соответствии с требованиями законодательства
* ❌ Не используйте для блокировки доступа к чужим ресурсам
